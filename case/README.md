# Evidence index: Case File 06

Everything here is fictional. Lessons read these files through `lantern.case`. Files marked
*planned* are not written yet; they are listed so every chapter knows where its evidence will be.

| File | What it is | First used | Status |
|---|---|---|---|
| `00-briefing.md` | Inspector Varma's briefing note, 13 July | 01 | written |
| `state/standing-orders.md` | The system prompt as it stands on 13 July: 35 rules, in the order they were added | 01 | written |
| `state/standing-orders/` | Every earlier version, and `changes.csv`: who added each rule, when and why | 04 | written |
| `state/case-memory.md`, `state/case-memory-history.csv` | The case memory, 16 entries, and who wrote each when. The first nine are the watch's memory of Case File 05 | 01 | written |
| `state/summaries/` | Four weekly session summaries, each written from the one before, and the June summary written from the weekly ones | 01 | written |
| `state/standing-notes.md` | Eight notes officers pinned for every session | 01 | written |
| `state/tools.json` | The schema of every tool LANTERN has been given since April, 19 of them, with the date each was added | 01 | written |
| `state/session-2026-07-13.jsonl`, `state/question.txt` | Monday morning's session so far, and the question of chapter 01 | 01 | written |
| `statements/` | Pellmar's reserve (MTB-31-02290) and client account (ICB-77-10458) as the banks reported them, 18 June to 6 July | 01 | written |
| `questions/` | The question set that depends on memory and context, with signed answers | 02 | planned |
| `memory-log/` | The access and write log of the memory store, with the session records behind each write | 12 | planned |
| `custody/` | DS Iyer's suspension and badge records, consistent with Case File 03 | 20 | planned |
| `review/` | The case review of chapter 22 | 22 | planned |

`state/` and `statements/` are generated by `scripts/build_case.py` (`make case`), and
`tests/test_case_facts.py` fails if they drift from it or from Case File 05.

Rules for every file: evidence is read-only. A lesson that needs a changed copy of anything
makes one under `.scratch/`. Stores and indexes are built under `.scratch/` and are never
committed.
